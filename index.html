✈️ GCP 上搭建 Telegram MTProto 代理

在自己的 GCP 虚拟机上用官方镜像搭一个 Telegram 专用代理：防火墙、Docker、secret、导入验证、运维与排障全记录（已脱敏，可公开）

在自己的 GCP 虚拟机（Debian 12）上用官方 MTProxy 镜像搭一个 Telegram 专用代理：给自己和信得过的人多一条连 Telegram 的路。本文命令均在 Debian 12 上适用，照着从上往下执行即可。

一、这是什么 / 先说清的几件事

  • MTProto 代理是 Telegram 官方协议的专用代理，只能代理 Telegram 流量，不能当通用代理用。官方软件由 Telegram 团队维护（TelegramMessenger/MTProxy），有现成的 Docker 镜像。
  • 装在哪：自己的 GCP VM（本文以一台 Debian 12 的小机器为例）。它是独立的 Docker 容器，和机器上其他服务（比如已有的节点）互不影响，不用了删容器即净。
  • 合规与成本：GCP 不禁止个人运行代理类软件。代理转发算普通出站流量——注意你实例的出站计费档位和免费额度，自己用离上限很远；真正的风险只有链接泄露被滥用刷流量，所以文中的 secret 只发给信得过的人，绝不公开。
  • 资源占用：极小，常驻内存十几 MB，1 GB 内存的小机器也毫无压力。

二、前置条件

  • 一台能 SSH 登录的 GCP VM（Debian 12），有一个公网 IP
  • 你的账号对该 VM 有 sudo 权限，对 GCP 项目有改防火墙的权限
  • 本地装有 Telegram 客户端（手机或桌面均可）用于导入和验证

三、步骤 1：GCP 防火墙放行 443/TCP

代理监听 443 端口（借用 HTTPS 的常用端口，较不易被网络单独针对；注意这只是端口选择，协议本身并没有伪装成 HTTPS——真正的协议伪装是 Fake TLS，见第九节），先在云端放行。

控制台操作：GCP 控制台 → VPC 网络 → 防火墙 → 创建防火墙规则：

  • 名称：allow-mtproto-443
  • 方向：入站；对匹配项执行的操作：允许
  • 目标：网络中的所有实例（或用目标标记只圈你的实例）
  • 来源 IPv4 范围：0.0.0.0/0
  • 协议和端口：TCP，443

或用 gcloud 命令（在本机装有 gcloud 的终端执行）：

gcloud compute firewall-rules create allow-mtproto-443 \
  --allow tcp:443 --direction INGRESS --priority 1000 --network default

如果机器上 443 已被其他服务占用，换一个端口（比如 8443），后面所有出现 443 的地方同步替换，防火墙也放行对应端口。注意 Docker 映射写宿主机端口在前：换 8443 时是 -p 8443:443，链接里的 port 也写 8443。

四、步骤 2：安装 Docker

SSH 登录 VM 后执行（已装 Docker 的跳过本节，用 docker --version 验证）：

curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
docker --version

能输出版本号即安装成功。官方安装脚本会把 Docker 设为开机自启。

五、步骤 3：生成 secret 并启动代理

先生成一个固定 secret（32 位十六进制）。固定 secret 的好处：代理链接由你自己拼，不依赖容器日志，重启也不变：

openssl rand -hex 16

把输出记下来（例如 0123456789abcdef0123456789abcdef，下文以 <SECRET> 代指）。再创建一个持久化数据卷（官方快速参考命令的标配）：

sudo docker volume create proxy-config

然后启动官方镜像：

sudo docker run -d --name mtproto --restart unless-stopped \
  -v proxy-config:/data \
  -e SECRET=<SECRET> \
  -p 443:443 \
  telegrammessenger/proxy
  • --restart unless-stopped：机器重启后容器自动恢复
  • -v proxy-config:/data：把配置和 secret 持久化到数据卷，升级或重建容器不丢。用上面固定 SECRET 的方式其实本来就不丢，这条是和官方写法对齐的双保险；如果你选择不传 SECRET 让它自动生成，数据卷就是必须的了——否则重建容器 secret 会变，所有人的链接都要重发
  • 想给不同的人发不同的 secret（便于单独吊销），-e SECRET= 后面可以用英文逗号分隔多个 secret
  • 不写 -e SECRET 也能跑：容器会随机生成并在日志里打印链接，但重启后排查麻烦，不推荐

确认容器起来了：

sudo docker ps

看到 mtproto 处于 Up 状态即可。

六、步骤 4：拼出代理链接并导入 Telegram

先在 VM 上查公网 IP：

curl -s ifconfig.me

代理链接格式（把 <公网IP> 和 <SECRET> 换成你的）：

tg://proxy?server=<公网IP>&port=443&secret=<SECRET>

同样的内容也有网页版链接，适合发给别人：

https://t.me/proxy?server=<公网IP>&port=443&secret=<SECRET>

导入方法：

  • 手机 Telegram：直接点开 tg:// 链接（或打开 t.me 链接），客户端会弹出「启用代理」确认框，点启用
  • 桌面 Telegram：设置 → 高级 → 网络与代理 → 添加代理 → 选 MTProto → 填服务器、端口、secret

七、步骤 5：验证

  1. 客户端里代理状态显示已连接（桌面版设置里能看到延迟毫秒数）
  2. 随便给一个联系人发条消息、再打开一个频道拉新消息，能收发即通
  3. VM 上看一眼容器日志，没有报错刷屏即正常：
sudo docker logs --tail 20 mtproto

八、日常运维

每日定时重启（官方建议，重要）

官方镜像说明里有一条容易被漏掉的建议：代理只在容器启动时拉取一次 Telegram 核心服务器的地址，官方建议约每天重启一次容器保鲜。--restart unless-stopped 只管崩溃和开机恢复，不做这件事，需要单独加一条定时任务（每天凌晨 4 点重启，秒级中断，基本无感）：

echo '0 4 * * * root /usr/bin/docker restart mtproto >/dev/null 2>&1' | sudo tee /etc/cron.d/mtproto-restart >/dev/null

验证已写入：cat /etc/cron.d/mtproto-restart。哪天想取消，删掉这个文件即可（卸载一节也会提到）。

命令速查

sudo docker ps                          # 看状态
sudo docker logs -f mtproto             # 实时日志（Ctrl+C 退出）
sudo docker restart mtproto             # 手动重启（顺带刷新核心服务器地址）
sudo docker stop mtproto                # 暂停代理
sudo docker start mtproto               # 恢复代理

换 secret：删容器后用新 secret 重跑第五节的启动命令，数据卷保留不用重建，然后把新链接发给使用者：

sudo docker rm -f mtproto

更新镜像：

sudo docker pull telegrammessenger/proxy
sudo docker rm -f mtproto
# 再执行第五节的启动命令（secret 和数据卷都在，不用重配）

九、进阶（可选，了解即可）：随机填充与 Fake TLS

基础版 secret 是纯随机串，流量特征就是 MTProto。有两个进阶抗探测选项，先说清它们的真实状态，避免照错资料踩空：

  • 随机填充（dd 前缀）：把 secret 改成以 dd 开头（dd + 原来的 32 位随机串），客户端发送时会给流量加随机填充，抗流量分析。这是协议层选项，改 secret 后所有客户端要换新链接，其他配置不用动。
  • Fake TLS（ee 前缀）：让连接看起来像访问某个正常网站的 TLS 流量，secret 形式为 ee + 随机部分 + 目标域名的十六进制编码。但要注意：官方 Docker 镜像的文档并不收录这种用法，它属于 MTProxy 程序本身及第三方实现（如 Telemt）的功能，配置也更复杂。本文基于官方镜像，就不给出 Fake TLS 的具体命令了——真要上，建议换源码版或第三方镜像再单独操作，别拿镜像版硬套。

十、排障速查

现象 先查什么
客户端一直「连接中」 GCP 防火墙 443 是否放行；sudo docker ps 容器是否 Up；公网 IP 是否填对
容器起不来 / 反复重启 sudo docker logs mtproto 看报错；多半是 secret 格式不对（必须是 32 位十六进制）
443 被占用导致启动失败 sudo ss -tlnp \| grep 443 看谁在占用，换端口并同步改防火墙和链接
导入链接没反应 检查链接参数：server 是公网 IP 不是内网 IP；secret 有没有多空格或漏字符
能连上但发不出消息 看日志有无异常；重启一次容器刷新核心服务器地址

十一、费用提醒（建议顺手做）

在 GCP 账单里设一个预算提醒兜底：控制台 → 结算 → 预算和提醒 → 创建预算，金额设一个小额（比如 $1），超阈值发邮件。这样万一链接泄露被滥用刷流量，你能第一时间收到通知，回来换 secret 止损。

十二、卸载（不想要了，干净清除）

sudo docker rm -f mtproto
sudo docker volume rm proxy-config        # 删数据卷（里面的 secret 一并清掉）
sudo rm -f /etc/cron.d/mtproto-restart    # 删每日重启定时任务
sudo docker rmi telegrammessenger/proxy   # 可选：连镜像一起删

然后到 GCP 控制台删掉 allow-mtproto-443 防火墙规则即可，不留开放端口。
